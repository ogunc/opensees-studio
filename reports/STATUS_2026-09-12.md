## 1 Summary

The codebase is healthy and internally consistent: 299 unit tests and 181 GUI tests all pass, all 28 example models load, and the strict `views -> viewmodels -> services -> core` layering holds with one documented exception.
Roadmap Phases 0 through 7 are complete; Phase 8 (earthquake engineering) is the active front and is roughly half done.
The one real risk found is environmental, not architectural: `pyproject.toml` pins OpenSeesPy 3.8.0.0, but the live `.venv` still has 3.5.1.12 on Python 3.11.5, so the bump in commit f86745f has never been exercised locally.
The full GUI suite cannot complete in a single process (VTK OpenGL context exhaustion, segfault at test 73), although every GUI test passes when files run in separate processes.
Documentation drift is the other soft spot: the gidopensees gap analysis is four months stale and now understates what has shipped.

## 5 Architecture check

The `core` layer is clean. No violations found.

**Import-level grep** over `src/opensees_studio/core/` for `PySide6`, `PyQt`, `openseespy`, `openseespywin`, `pyvista`, `vtk`, and `pyqtgraph` at statement position returned **zero matches**.

A broader grep for any textual mention of those names inside `core/` returned only three hits, all of them prose in docstrings asserting the rule rather than breaking it:

- `core/__init__.py:3`, "This package never imports Qt or openseespy."
- `core/defaults.py:10`, notes the convenience "used to live in the Qt tool/command layer".
- `core/defaults.py:13`, "It is Qt-free and openseespy-free, like the rest of `core`."

A grep for the bare token `Qt` in `core/` found the same three prose lines and nothing else. Matches inside `__pycache__/*.pyc` are compiled artifacts of those same docstrings and are not source.

**Runtime proof**, which is stronger than grep because it also catches transitive imports:

```
>>> import sys, opensees_studio.core
leaked: NONE        # checked PySide6, pyvista, vtk, pyqtgraph, pyvistaqt
```

**Dependency direction.** A grep in `core/` for imports of `views`, `viewmodels`, `services`, or `commands` returned zero matches, so `core` has no upward dependencies.

**Adjacent layers, checked as corroboration:**

| Rule | Result |
|---|---|
| `core` imports no Qt and no openseespy | PASS (grep and runtime) |
| `core` imports no upper layer | PASS |
| `views` never imports openseespy directly | PASS, zero matches |
| `services` imports no Qt | one documented exception, see below |

The exception is `src/opensees_studio/services/qt_workers.py:24`, which does `from PySide6.QtCore import QObject, Signal, Slot`. This is deliberate and contained, not drift:

- Its module docstring states the intent: "Imports PySide6, keep it isolated from the rest of `services`; the runner itself remains Qt-free."
- `services/__init__.py` documents it as "the only module here that imports PySide6" and, critically, does not import it.
- Its only consumer is `viewmodels/analysis_runner.py:15`, which is a Qt-aware layer by design.
- Runtime confirmation that the headless path stays clean: `import opensees_studio.services` leaves `PySide6` out of `sys.modules` (checked, returns `False`).

So the headless tier promised by ADR-0002 genuinely holds. The only action worth considering is a wording tweak in CLAUDE.md, which currently says services has "No Qt" without noting the one sanctioned bridge module.

## 7 Open items and next candidate phase

Recommendations only. No work was started on any of these.

### 7.1 Blocking or high risk

1. **The OpenSeesPy 3.8.0.0 pin is unvalidated.** `pyproject.toml` pins `openseespy==3.8.0.0` and `openseespywin==3.8.0.0` (lines 29 and 30), but the live `.venv` runs 3.5.1.12 on Python 3.11.5. CLAUDE.md itself says the 3.8.0.0 wheel has no 3.11 build on Windows and requires 3.12+, so the current `.venv` cannot install the pinned version. Commit `f86745f` bumped the pin without a local environment able to exercise it, and the 55 integration tests (the only ones that call real openseespy solves) have therefore never run against 3.8.0.0 here. This is the highest-value next action: build a Python 3.12 venv, install the pinned versions, and run `pytest tests/integration`. Note also that `requires-python` is still `>=3.10`, which is inconsistent with the Windows 3.12+ requirement and may deserve an environment marker.

2. **The GUI suite cannot run as one process.** Single-process `pytest tests/gui` segfaults at test 73 on VTK `wglMakeCurrent` failures. This makes the command documented in CLAUDE.md unusable as written, and will break CI on any Windows runner with a real GL context. Options: add a session-scoped plotter fixture that tears down VTK render windows properly, force `pyvista.OFF_SCREEN` in the GUI conftest, or shard GUI tests per file in CI. All 181 tests pass in isolation, so this is a harness problem rather than a product defect.

### 7.2 Documentation drift

3. **Refresh `docs/gap-analysis-gidopensees.md`.** Dated 2026-05-22 and now four months stale. Verified against current `core/`: Concrete04, ImposedSupportMotion, and HystereticSM have shipped but are still listed as missing. Of the 22 P1 rows, the genuinely open ones are ConcreteCM (Chang-Mander), TrigTimeSeries (needed for sine ground motion), RigidDiaphragm, RigidLink, Viscous and Viscous_Damper (Maxwell), ShellMITC4 and ShellDKGQ, Elastic Timoshenko beam-column, ReinforcingSteel (DoDD-Restrepo), FiberInt (P-M interaction), Series and Parallel combinations, Elastic_Perfectly_Plastic_with_Gap, the line and point constraint variants, Line_Mass, and per-region Rayleigh.

4. **Resolve ADR-0001.** Still marked Proposed with a DEFERRED note on unit handling, even though the codegen it describes shipped in `0325bc8`. It should move to Accepted with the units carve-out recorded explicitly, or be superseded by a new ADR.

5. **Correct the services layering note in CLAUDE.md.** It says `services` has "No Qt", but `services/qt_workers.py` imports PySide6 by design. The architecture is sound (section 5); only the wording is wrong.

6. **No CLAUDE_CODE transition document exists in the repo.** If one is meant to be tracked here, it is missing and should be committed.

### 7.3 Code and hygiene

7. **379 TODO markers, all one theme.** Every `TODO`, `FIXME`, `HACK`, and `XXX` in `src/` is the identical marker `# TODO: unit-aware type` inside `core/catalog/generated/`, attached to fields typed as `str` holding values like `'-20 MPa'` and `'500 MPa'`. There are zero TODO or FIXME comments anywhere outside the generated catalog, which is a genuinely clean signal. All 379 are downstream of the deferred units decision in ADR-0001, so resolving units closes them at once. Until then those catalog fields are stringly typed and unvalidated.

8. **Delete the stale `venv/`.** Python 3.9.1, no pytest, superseded by `.venv`. Two virtualenvs in the root invites running tests against the wrong one, which is exactly the confusion this audit had to resolve first.

9. **Relocate or remove `Ex2.csv` and `Ex2.png`** from the repo root, and confirm whether `examples/ozan.osmodel` belongs in the catalogued example set.

10. **Remove the phantom GUI dependencies, or document why they stay.** `pyproject.toml` lists `scipy>=1.11` and `pandas>=2.1` in the `gui` extra with an inline comment admitting they "are not currently imported by any module in this repo (phantom deps as of 2026-06-15)". They inflate desktop install size for nothing.

### 7.4 Next candidate phase

The natural next phase is **completing Phase 8**, and the ordering within it is fairly clear.

Start with item 1 above, validating the 3.8.0.0 pin on Python 3.12, because it is a correctness gate: every Phase 8 feature lands on top of the runner, and the runner has not been proven against the pinned OpenSeesPy. Fix item 2 next, so the GUI suite yields a single trustworthy signal instead of a per-file workaround.

Then the highest-value Phase 8 feature work, in order:

- **Material Tester dialog.** The headless service is done, verified, and Qt-free, so only the front-end is missing. Lowest effort for visible progress, and it makes every subsequent material addition easier to validate by hand.
- **Rigid diaphragm and rigid link constraints.** Confirmed absent from `core/`. These are prerequisites for realistic multi-storey building models, and their absence is part of why no example exceeds 64 elements.
- **Seismic isolators**, the largest remaining roadmap block, and the one most aligned with the project's stated goal of being a research tool rather than an OpenSees frontend.
- **Ground-motion library and IDA runner** after that, since both depend on record handling that the missing `TrigTimeSeries` and the record-library gap currently block.

Defer the **Phase 7 render performance pass** until a model large enough to measure it exists. Consider adding one as an example, since the 10k node target is currently untestable with the shipped example set.
